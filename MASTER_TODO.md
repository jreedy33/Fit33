### 0.2 Notes

- The Phase 1a migration is intentionally **not** auto-deployed — `assn-webhook` env vars (`ASSN_BUNDLE_ID`, `ASSN_VERIFY_SIGNATURE`) must be set in Supabase Functions secrets BEFORE running the SQL, so the webhook is ready to receive Apple's first event the moment the URL is registered in App Store Connect.
- `ASSN_VERIFY_SIGNATURE` ships defaulting to `false` (audit-only). Flip to `true` only AFTER end-to-end sandbox + production cert chain validation lands — Apple's cert rotates and a too-strict validator can drop legitimate events. Until then, `is_signature_valid=false` rows are logged but never mutate state, which is the safest posture during bring-up.
- `PremiumManager.serverEntitlement` is **observability-only in Phase 1c**. Do NOT ship a "client/server disagree → downgrade" code path until the paywall lands; doing so would lock everyone out of features for the indeterminate window between schema deploy and webhook URL registration.
- After Phase 1a deploys, the CMS `/revenue` tab automatically lights up — the page already probes `revenue_daily_rollup` and switches its render mode based on `schema_deployed`. No CMS code change needed at deploy time.
